# Experimental Deviations Log

This document records deviations, design alterations, and methodology shifts made during the lifecycle of the project.

| Date | Change | Reason |
| 2026-10-10 | Synthetic benchmark validation executed (v0.1-synthetic) | Success criterion failed: GatedModel utility does not cross zero (S*=None in ~99% resamples, MI=None) against 'zeros' and 'mean' null variants because GatedModel dampens pure noise more than zero/mean vectors, keeping S=1 accuracy above null accuracy. FixedModel exhibits MI ~0.75 (zeros) and ~0.59 (mean). Parameters left untouched per protocol awaiting direction. |
| 2026-10-10 | Primary null changed from zeros/mean to removed after v0.1 results | Zeros/mean synthetic vectors produced biased centroid distances causing GatedModel null accuracy to drop below pure-noise accuracy. 'removed' (X_A=None) serves as true unimodal ablation. Also fixed summary aggregation to use pooled bootstrap so point estimates lie strictly within CIs, adding across-seed std and bootstrap stability columns. |
| 2026-10-10 | Synthetic benchmark iteration v0.3: criterion revised post hoc, MI clipping finding, hierarchical bootstrap added | Criterion revised post hoc after v0.2 to evaluate oracle baseline (<0.05), fixed threshold (>0.7), model ordering (gated < partial < fixed) with non-overlapping hierarchical CIs, and monotonicity across gamma_scale sweep {0.5, 1, 2, 4, 8, 16}. MI clipping investigated: under null 'removed', noisy modality A pushes R(S) > R(0) as S -> 1, causing unclipped MI to reach 1.33-1.80 for Fixed and 1.15-1.54 for Partial; np.clip(mi, 0.0, 1.0) in misalignment_index caps both at 1.0000, resulting in CI overlap [1.00, 1.00]. Two-level hierarchical bootstrap (resample seeds, then items within seeds) added alongside pooled bootstrap. PartialGatedModel/mean lower bound explained: 49% of bootstrap resamples reach S*=1.0 where boundary MI=0.0. |
| 2026-10-10 | v0.4: MI upper clip removed from misalignment_index; S*=last-grid-point returns None; paired bootstrap added | (1) Authorized metric fix: removed np.clip(mi, 0.0, 1.0) from misalignment_index so MI can exceed 1 when R_hat(S)>1 after S*, reflecting genuine hyper-reliance on a degraded modality. Docstring updated accordingly. (2) Authorized metric fix: S* at or beyond the last grid point now returns None (was 0.0), consistent with no-crossing semantics, because the integration interval [S*, 1] is empty. Callers treating None as no-crossing are unchanged. (3) Paired bootstrap over seeds+items (n_boot=1000) added post hoc to Task 3 to test ordered MI differences MI(fixed)-MI(partial) and MI(partial)-MI(gated) for null='removed'. All changes derived from v0.3 raw data (write-once); no raw files were modified. Results aggregated into synthetic_summary_v04.csv. |
| 2026-10-10 | v0.5 VLM pilot: answer format adapted from open-ended first-token to 4-option multiple choice | Smoke test on Qwen2-VL revealed first-token probability distributions are diffuse for open-ended generative answers. To obtain clean, well-formed next-token probability vectors, the pilot evaluation format was adapted to 4-option multiple choice (A-OKVQA benchmark), reading the renormalized next-token distribution over letter tokens ['A', 'B', 'C', 'D'] at the final prompt position. Full-vocab probability mass on these 4 tokens is tracked and logged. |
| 2026-10-11 | v0.7 VLM main benchmark: swapblend corruption added, S* edge and significant crossing rules formalized post hoc, disjoint N=500 sample drawn | Pilot Criterion 2 was judged a weak pass because Gaussian utility crossed zero only at the final grid point (S*=1.0), which yields no usable integration interval for MI, while patch mask utility did not cross zero (acc stayed above null). To induce genuine cross-modal utility inversion, a third corruption 'swapblend' ((1-S)*img + S*img_other via fixed seeded derangement) was added. Formalized analysis rules post hoc: (1) S* at the grid edge is reported as 'edge, no usable crossing'; (2) a significant crossing metric was defined as the first S where the upper bootstrap CI of U(S) < 0. Multi-model adapter architecture added supporting Qwen2-VL, SmolVLM, and InternVL2 with a --check mode (letter mass >= 0.90 threshold). Fresh sample of N=500 items drawn strictly disjoint from pilot items (results/derived/main_ids.json). |
| 2026-10-11 | v0.7.1 SmolVLM token variants: letter probabilities sum bare and space-prefixed tokens | Pre-flight validation (--check) on SmolVLM-Instruct revealed 90% clean accuracy with sensible answer distributions, but reported mean letter probability mass 0.0000. In SmolVLM's BPE vocabulary, the first generated token uses space-prefixed variants (' A' id 330, ' B' 389, ' C' 340, ' D' 422) rather than bare letters ('A' id 49, ' B' 50, ' C' 51, ' D' 52). The SmolVLM adapter (only) was updated to compute each letter's probability as the sum of full-vocab softmax probabilities over both variants, tracking total mass across all 8 tokens and renormalizing across the 4 choices. Qwen2-VL adapter and existing results remain untouched; no SmolVLM benchmark results existed prior to this fix. |
| 2026-10-11 | Pre-registered hypothesis: swapblend reliance-utility expectation (prior to main benchmark analysis) | Pre-registered expectation: under swapblend (deceptive/swapped visual context), if multimodal utility U(S) drops clearly negative at high severity (S >= 0.75) while normalized reliance R_hat(S) remains above 0.50, the model exhibits empirical multimodal over-trust (reliance-utility misalignment). Conversely, if R_hat(S) falls monotonically toward zero as U(S) degrades, the model exhibits quality-aligned reliance discounting. |
| 2026-10-11 | v0.7.2 InternVL2 loading: removed device_map="auto" to resolve remote-code incompatibility | Pre-flight validation (--check) on InternVL2-2B crashed in AutoModel.from_pretrained with AttributeError: 'InternVLChatModel' object has no attribute 'all_tied_weights_keys' caused by device_map="auto" under newer transformers. In the InternVL2 adapter (only), removed device_map, loaded with low_cpu_mem_usage=True and trust_remote_code=True, and explicitly transferred to device via .eval().to(device). No InternVL2 results existed prior to this change. |
| 2026-10-11 | v0.7.3 InternVL2 dropped: persistent remote-code incompatibility with transformers>=4.50 | Second pre-flight attempt with loading fix (v0.7.2) failed at the same point: transformers.modeling_utils._move_missing_keys_from_meta_to_device references self.all_tied_weights_keys which InternVLChatModel (remote code) does not define. The error is inside transformers core, not in our adapter, and cannot be patched without pinning an older transformers version incompatible with the Kaggle environment. Per the bounded-debugging protocol (max 30 minutes), InternVL2-2B is dropped from the study. The main benchmark proceeds with two models: Qwen2-VL-2B-Instruct and SmolVLM-Instruct. InternVL2 incompatibility is listed as a study limitation. |
| 2026-10-11 | v0.7.3 SmolVLM readout adapted via assistant prefix after mass check failure | Despite 90% clean accuracy (correct logit ranking), SmolVLM's mean probability mass on bare + space-prefixed letter tokens was 0.0017 under the default prompt template, failing the mass >= 0.90 gate. The model's first generated token is a conversational preface, not a letter. To bring the readout position to a letter token, an optional assistant pre-fill prefix was added to the SmolVLM adapter only. Two named variants are available: 'answer_colon' ('Answer:') and 'the_answer_is' ('The answer is'). Protocol: at most two variants are tried on Kaggle via --check; the chosen variant is selected only by mass >= 0.90, not by accuracy; if neither passes, SmolVLM is also dropped. The prefix is applied identically across every condition (clean, removed, black, all corruptions). Qwen2-VL adapter and results are untouched. No SmolVLM benchmark results existed prior to this change. |
| 2026-10-11 | v0.8 LLaVA-1.5-7B added as 4-bit NF4 replacement for InternVL2 | LLaVA-1.5-7B-hf (llava-hf/llava-1.5-7b-hf) is added as the third model, replacing InternVL2 which was dropped due to remote-code incompatibility with transformers>=4.50. LLaVA is loaded in 4-bit NF4 quantisation via BitsAndBytesConfig (compute_dtype=float16, device_map={"": 0}) to fit on a T4 GPU. Protocol: at most two prefix variants are tried via --check ('answer_colon' then 'the_answer_is'); the chosen variant is selected only by mass >= 0.90, not by accuracy; if neither passes, LLaVA is also dropped and the study proceeds with two models only. No LLaVA benchmark results exist prior to this entry. |
| 2026-10-11 | Pre-registered hypotheses: Modality-dropout case study (H1, H2, H3) | Pre-declared prior to any training code: H1: models trained with higher modality-dropout probability p have lower MI under the 'removed' null (MI non-increasing in p, allowing ties within CI). H2: clean accuracy drops by less than 3 percentage points between p=0 and p=0.25. H3: if H1 fails, report it; do not change datasets or p grid to rescue it. Decision logged: null = modality A removed with learned null token; optimizer AdamW lr=1e-3, weight_decay=1e-4; p in {0, 0.1, 0.25, 0.5}, 5 seeds {0..4}; training split for training only, select nothing on test split, report test split once. |
| 2026-10-11 | v0.13.2 Qwen main swapblend outcome vs pre-registered criterion | Empirical outcome for swapblend under Qwen2-VL-2B-Instruct ($N=500$) is mixed relative to pre-registered criterion ($U(S) < 0$ at $S \ge 0.75$ while $\hat{R}(S) > 0.50$): at $S=0.75$, utility remains positive ($U=+0.0780$, 95\% CI $[+0.0280, +0.1240]$) and $\hat{R}=0.5240$ $[0.4805, 0.5695]$; utility inversion occurs slightly later at $S^*=0.875$ ($U=-0.0180$, 95\% CI $[-0.0680, +0.0300]$) with $\hat{R}=0.4824$ $[0.4344, 0.5334]$; at $S=1.0$, utility is strictly negative ($U=-0.0640$, 95\% CI $[-0.1141, -0.0180]$) with significant crossing confirmed at $S=1.0$, while $\hat{R}=0.4872$ $[0.4366, 0.5422]$ (95\% CI contains 0.50). Normalized Misalignment Index $\text{MI} = 0.4848$ (95\% pooled CI $[0.4448, 0.5368]$). Results reported directly without post hoc adjustments. |
